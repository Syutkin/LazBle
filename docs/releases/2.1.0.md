# LazBle 2.1.0

LazBle 2.1.0 uses SimpleDelphiBLE 1.4.0 and its official Lazarus runtime
package. It adds GATT descriptor operations, indications, configurable runtime
loading, Battery Service 1.1 data, and a Device Information Service profile.

## Highlights

- Read and write descriptors with `ReadDescriptorAsync` and `WriteDescriptorAsync`.
  Receive indications with `SubscribeAsync(..., lbsmIndicate)` using the same
  subscription interface as notifications.
- Set `TLazBle.LibraryPath` before the first native call to select a runtime
  file or directory. The native library loads on demand; a missing runtime
  fails the BLE operation without preventing application startup.
- Use `TBleBatteryProfile.Data`, `OnUpdated`, and `RefreshAsync` for Battery
  Service 1.1 status, energy, time, health, and identity data for one battery.
  `LevelPercent` and `OnLevelChanged` remain available, including on read-only
  devices.
- Read device identity through `TBleDeviceInformationProfile`, with typed
  System ID, PnP ID, and UDI fields and explicit refresh of complete snapshots.
- Send long buffers through `TBleByteChannel`; it splits each send into ordered
  writes that fit the connection's payload limit and returns one operation
  for the whole buffer.
- NUS uses writes without response when supported, otherwise writes with response.

## Upgrading from 2.0.0

Download the official [SimpleDelphiBLE 1.4.0 distribution](https://github.com/simpleble/simpledelphible/releases/tag/v1.4.0).
Replace both the binding sources and the native runtime with files from that
distribution. Register `SimpleDelphiBLEPackage.lpk` before the LazBle packages
and rebuild the packages and application. Native linker paths are no longer
needed. Deploy the single SimpleCBLE runtime for the target platform.

See the [README](../../README.md#dependencies-and-native-libraries) for package
registration, runtime names, and executable/system library search paths.

- Scan explicitly before connecting an unknown DeviceId. `ConnectAsync` uses
  an earlier scan, an existing connection, or the paired-device list; it does
  not start a scan itself.
- Subscriptions validate the discovered characteristic's Notify or Indicate
  capability. Select `lbsmIndicate` explicitly when required by the device.
- `TBleByteChannel.SendAsync` now splits oversized buffers. One send still
  returns one operation, and consecutive sends do not interleave. Message
  framing remains the application's responsibility.
- Replace `TLazBleDeviceControl` instances in forms with application-owned LCL
  controls bound to `TLazBleLclClient`. The [LCL demo](../../examples/lcl/lazblelcldemoform.pas)
  shows device selection, connection actions, status display, and shutdown.

Continue to access LazBle on the main thread and await `ShutdownAsync` before
freeing active owners. Shutdown preserves accepted operation outcomes and
reports cleanup failures after client sessions close.
